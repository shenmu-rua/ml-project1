# C：道路事故分级评估与解释

本次审计使用项目 MLflow 注册库中的 `models:/road-severity-model/5`，对应 `LGBMClassifier`，训练 run 为 `4557265462694f7dbd9b1836225a0d7c`。复核时 `production` 指向该版本。评估与 SHAP 共用注册库配置，并支持按版本复现。

## 1. 冻结测试集上的分级表现

时间切分包括 115,535 条训练记录、24,636 条验证记录和 24,679 条测试记录。测试窗口为 2025-09-25 至 2025-12-31。正类取官方记录中的致死或重伤。危及生命事故按有细分伤情记录的警区统计，致死漏判率使用全部致死记录。

| 测试集验收项 | 项目要求 | v5 实测 |
| --- | --- | --- |
| 危及生命事故进入三级 | ≤ 5% | 3.79% |
| 致死事故进入三级 | ≤ 1% | 0.27% |
| 三级占全部事故 | ≥ 20% | 25.82% |
| 一级中危及生命事故的富集倍数 | ≥ 3 倍 | 3.52 倍 |

原始分数达到 0.6864 进入一级，低于 0.2198 进入三级，其余进入二级。按模型保存的完整精度计算，三级分别覆盖 12.77%、61.41%、25.82%（按一、二、三级顺序）。368 起致死事故中有 1 起进入三级。一级中危及生命的比例为 21.98%，支持优先核实。分级由 `src/triage.py` 定义。

| 指标 | v5 原始测试分数 |
| --- | --- |
| PR-AUC | 0.5060 |
| ROC-AUC | 0.7415 |
| F1（0.5 阈值） | 0.5080 |
| 精确率 / 召回率 | 0.4502 / 0.5829 |
| 平衡准确率 | 0.6698 |
| Brier / log-loss | 0.1874 / 0.5519 |
| ECE（10 个等频分箱） | 0.1449 |

重新预测测试集后，23 项二分类与分级指标和上述 run 的记录逐项一致，最大绝对差为 0。ECE 由评估模块单独计算。历史模型的指标和训练过程见 [B 的建模报告](report_B_modeling.md)。

## 2. 概率校准实验

按时间将验证集分成两段。前 16,423 条拟合候选校准器，后 8,213 条评估 log-loss。时间分界为 2025-08-19 10:15 UTC，同一时刻的记录属于同一侧。

| 候选方法 | 留出段 Brier | 留出段 log-loss |
| --- | --- | --- |
| isotonic | 0.1655 | 0.5067 |
| sigmoid | 0.1654 | 0.5029 |

按留出段 log-loss 选中 sigmoid，在全部验证数据上重拟合，再评估冻结测试集。

| 测试集指标 | 线上原始分数 | 离线 sigmoid |
| --- | --- | --- |
| Brier | 0.1874 | 0.1618 |
| log-loss | 0.5519 | 0.4929 |
| ECE | 0.1449 | 0.0076 |
| PR-AUC | 0.5060 | 0.5060 |
| ROC-AUC | 0.7415 | 0.7415 |

在验证集上按分位点重映射的实验界线为 **0.1275 / 0.4608**。测试集三级占比为 25.82%，四项验收均通过。分位点插值可能移动边界附近的样本。可靠性曲线见 `artifacts/evaluation/reliability_test.png`。API 仍返回 v5 的原始分数，并使用原始界线。

## 3. 分级界线与运力

两条原始界线来自验证集。上界对应最高 15% 的分数，下界按验证集危及生命事故的分数确定。下表固定上界，只移动下界，度量冻结测试集上的变化。

| 下界偏移 | 下界值 | 危及生命漏判率 | 三级占比 | 四项验收 |
| --- | --- | --- | --- | --- |
| -0.02 | 0.1998 | 3.02% | 22.78% | 通过 |
| -0.01 | 0.2098 | 3.30% | 24.32% | 通过 |
| 0.00 | 0.2198 | 3.79% | 25.82% | 通过 |
| +0.01 | 0.2298 | 4.35% | 27.27% | 通过 |
| +0.02 | 0.2398 | 4.91% | 28.75% | 通过 |

下调下界使更多事故进入紧急队列，可以减少漏判，同时增加优先处置量。上调下界能释放优先处置运力，也会增加漏判。上调 0.02 后，漏判率达到 4.91%，已接近 5% 的项目上限。验证集扫描曲线见 `cutoff_tradeoff_val.png`。调整实际派单规则前应另取时间窗口复核。

## 4. 时间稳定性

取训练窗口最后 40,000 条记录，使用生产 LightGBM 的超参数进行四折顺序交叉验证。每折重新拟合特征管线，并对训练样本使用伤情权重。该比较未使用正式训练的信息缺失增广。

| 折 | 训练行数 | 验证行数 | PR-AUC | ROC-AUC |
| --- | --- | --- | --- | --- |
| 1 | 8000 | 8000 | 0.4458 | 0.7152 |
| 2 | 16000 | 8000 | 0.4780 | 0.7260 |
| 3 | 24000 | 8000 | 0.5051 | 0.7363 |
| 4 | 32000 | 8000 | 0.4841 | 0.7305 |

四折 PR-AUC 为 0.4782 ± 0.0212，ROC-AUC 为 0.7270 ± 0.0077。这些区间给出折间标准差；窗口内正例构成变化也会影响 PR-AUC。

## 6. SHAP 解释

在测试集固定抽取 2,000 条记录（随机种子 42）。每条记录的基准 log-odds 加上所有贡献后，经 sigmoid 转换应还原生产管线的原始分数。单样本与全局入口都执行该检查，XGBoost 保留推理时的稀疏输入。单样本返回的 `other_impact` 汇总展示范围以外的贡献。

| 信息组 | 平均绝对 SHAP 贡献占比 |
| --- | --- |
| 车辆与驾驶员（含碰撞过程） | 46.53% |
| 伤亡人员 | 27.85% |
| 道路与环境 | 10.88% |
| 地点 | 6.09% |
| 时间与日照 | 5.97% |
| 天气观测 | 2.68% |

`shap_beeswarm.png` 展示编码特征对不同样本的影响方向，`shap_importance.png` 给出平均绝对贡献，`shap_group_importance.json` 保存分组占比。填报渠道可能影响缺失或未知编码，SHAP 所示关联本身不能确定事故成因。

## 7. 漂移与适用边界

本次 Evidently `DataDriftPreset` 使用训练集作为参考、测试集作为当前窗口，225 个受检字段中有 **13 个（5.78%）** 被标记，低于数据集层面的 50% 阈值。相对湿度、气温和气压的标准化 Wasserstein 距离分别约为 0.54、0.33 和 0.28。道路表面状况和照明的 Jensen–Shannon 距离均约为 0.14。完整逐列结果见 `drift_report.html`。

当 Evidently 无法计算时，程序为具有足够观测的数值列生成独立的 PSI CSV。首尾分箱覆盖参考范围以外的值。两侧各至少需要 50 个有限观测；没有合格列时返回 `insufficient_data`。该回退与 Evidently 使用的统计量分开报告。

上述整体分级验收适用于完整现场信息。B 对 v5 的缺失实验显示，同时缺少车辆和伤亡信息时，93.1% 的事故进入二级；只缺伤亡信息时，致死漏判率约 1.1%。跨季节、跨地区使用时需要再次核实分级与校准表现。实际调度保留人工判断。

## 8. 复现

使用项目 uv 环境、冻结的 `data/road_collisions.sqlite` 和包含上述 run 的 MLflow 注册库。从项目根目录执行以下命令。远端注册库通过 `MLFLOW_TRACKING_URI` 配置；默认使用项目的 `mlflow.db`。

```bash
uv run --no-sync python -m src.evaluate --model-version 5
uv run --no-sync python -m src.explain --model-version 5
uv run --no-sync python -m pytest tests -q
```

两条入口都会接受 `--model-version`；省略时使用执行时的 `production` 别名。复核本报告请同时核对版本和 run ID。`artifacts/evaluation/metrics.json` 包含模型身份、23 项对账、候选方法的留出成绩、分群、阈值和交叉验证结果。使用 `--max-rows N` 的抽样运行写入单独的 `sample-N` 目录。
