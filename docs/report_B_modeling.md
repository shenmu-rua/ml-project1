# 训练与实验追踪（B）

用途：辅助急救调度在接警时按轻重缓急派出力量。模型根据现场可获得的信息给每起事故一个严重程度概率，并据此输出三级派单优先级。
当前线上模型：`models:/road-severity-model@production`（版本 5，LightGBM，完整 Pipeline + 三级优先级界线）。

结论先行：

- **不能当“严重 / 不严重”的判定器用。** 召回 85% 时精确率只有约 35%，现有公开数据达不到“召回 85% 且精确率 60%”（见第 4.3 节）。
- **可以当分级排序工具用，并通过了本项目设定的最低验收。** 测试集上，最低一级（常规）占 25.8% 的事故，其中危及生命的只有 0.9%；
  最高一级（立即）占 12.8%，危及生命的比例是整体的 3.5 倍；危及生命的事故只有 3.8% 被排到最低一级，致死事故只有 0.3%（见第 4.1 节）。

第 1–3 节的数字来自版本 3 的模型搜索；版本 5 沿用它选出的模型族和超参，只改了样本权重和输出方式（见第 5 节）。

| val | 2025-06-15 ~ 2025-09-24 | 24,636 | 26.8% |
| test | 2025-09-25 ~ 2025-12-31 | 24,679 | 25.5% |

版本 3 在完整信息下、把它当二分类器（阈值 0.5）时的表现，用于和历史版本比较；线上实际的分级方式见第 4 节：

| 切分 | PR-AUC | ROC-AUC | F1 | 精确率 | 召回 | 平衡准确率 | Brier |

各模型都按类别频率的倒数加权，这会整体抬高预测概率；概率校准由 memberC 负责。

## 2. 需要哪些信息，各占多少权重

模型输入共 226 列（编码后 313 维），按来源分为 7 类。权重是 LightGBM 的分裂增益占比（合计 100%）。

| 信息类别 | 权重 | 包含的字段 | 来源 |
|---|---|---|---|
| 车辆与驾驶员属性 | 25.1% | 车辆类型、左/右舵、排量、驾驶员年龄与性别、出行目的、驾驶员居住地贫困指数、动力类型、是否电动滑板车、牵引情况 | 车辆表 |
| 伤亡人员描述 | 23.7% | 伤亡人员类型、年龄、是否客车乘客、性别、居住地贫困指数、行人位置与动作、人员类别、是否轿车乘客 | 伤亡表 |
| 碰撞过程 | 17.5% | 是否驶离车道、首次撞击点、车辆动作、相对路口位置、撞击车道外/车道内物体、侧滑翻车、是否在限制车道 | 车辆表 |
| 地点 | 11.5% | 纬度、经度 | 事故表 |
| 时间与日照 | 9.7% | 小时、太阳高度角、星期、月份、昼夜阶段 | 事故时间推算 |
| 天气观测 | 7.3% | 气压、气温、风向风速分量、相对湿度、降水 | 天气表 |
| 道路与环境 | 5.3% | 限速、道路类型、城乡、道路等级、车辆数量、路口类型与管制、人行横道、照明、天气与路面状况编码 | 事故表 |

权重最高的单个字段：

| 字段 | 权重 | 字段 | 权重 |
|---|---|---|---|
| 伤亡人员类型 `casualty_type` | 8.6% | 首次撞击点 `first_point_of_impact` | 4.2% |
| 纬度 `latitude` | 6.8% | 排量 `engine_capacity_cc` | 3.9% |
| 伤亡人员年龄 `age_of_casualty` | 6.0% | 驾驶员年龄 `age_of_driver` | 3.6% |
| 车辆类型 `vehicle_type` | 5.7% | 车辆动作 `vehicle_manoeuvre` | 3.4% |
| 经度 `longitude` | 4.7% | 是否客车乘客 `bus_or_coach_passenger` | 3.0% |
| 左/右舵 `vehicle_left_hand_drive` | 4.5% | 小时（周期编码） | 5.2% |
| 是否驶离车道 `vehicle_leaving_carriageway` | 4.3% | 驾驶员性别 `sex_of_driver` | 2.8% |

解读时注意三点：

- **增益会高估连续变量。** 天气观测的增益有 7.3%，但把它整组去掉后测试集指标不变（见第 3 节）。更可靠的权重是“去掉这类信息后指标掉多少”。
- **“未知”编码在起作用。** `vehicle_left_hand_drive`、`sex_of_driver` 的权重主要来自“未知”这一取值，它反映的是记录方式（如信息不全的自助报案多为轻微事故），不是物理原因。
- **伤情结论不进模型。** `casualty_severity` 等 5 个字段是标签本身，已在 `schema.json` 的 `excluded_outcomes` 中排除，代码有防误用检查。伤亡人员的类型、年龄、人数属于现场可得信息，按项目目标保留。
  `age_of_vehicle` 因 2025 年 6 月后全部缺失（DfT 脱敏）也被排除。

## 3. 信息不全时的预测

只有时间和经纬度是必填的（用于推算日照）；其余信息按 4 组可整组缺失：天气观测、道路与环境、车辆、伤亡人员。

用法：`complete_inputs` 把缺少的列补成缺失值，再交给模型。

```python
from src.features import complete_inputs
model.predict_proba(complete_inputs(partial_frame))[:, 1]
```

车辆和伤亡人员的输入由 `src.participants.aggregate` 从现场填报的列表聚合得到。

各类信息缺失时的测试集表现（版本 3，阈值 0.5；分级方式下的表现见第 4.2 节）：

| 缺失的信息 | PR-AUC | ROC-AUC | F1 | 召回 | 相对完整信息的 PR-AUC 变化 |
|---|---|---|---|---|---|
| 无（完整信息） | 0.4992 | 0.7404 | 0.512 | 0.657 | — |
| 天气观测 | 0.5015 | 0.7417 | 0.515 | 0.666 | +0.002 |
| 道路与环境 | 0.4838 | 0.7343 | 0.506 | 0.660 | −0.015 |
| 车辆 | 0.4593 | 0.7127 | 0.486 | 0.593 | −0.040 |
| 伤亡人员 | 0.4363 | 0.6987 | 0.468 | 0.579 | −0.063 |
| 车辆 + 伤亡人员 | 0.3600 | 0.6257 | 0.413 | 0.534 | −0.139 |

适配方法：训练时把 50% 的训练行复制一份，并随机抹掉其中至少一组信息（每组各 50% 概率），与原始行一起训练。
预处理的统计量（中位数、缩放、类别）仍只来自原始训练行。

适配的必要性：版本 2 没有做这一步，缺失值被填成中位数后，模型把“没有信息”当成“一起典型事故”。
车辆和伤亡信息都缺失时，版本 2 的测试集 PR-AUC 只有 0.335、ROC-AUC 0.591，比只用 21 个输入的版本 1 还差。
版本 3 把这一场景拉回到 0.360 / 0.626，代价是完整信息下 PR-AUC 降 0.003。

仍存在的不足：车辆和伤亡都缺失时，版本 3（0.360 / 0.626）仍略低于专门用 21 个输入训练的版本 1（0.373 / 0.643）。

## 4. 三级派单优先级与验收

### 4.1 输出方式与验收结果

`model.predict()` 返回优先级，`model.predict_proba()` 返回严重程度概率，`model.pipeline` 是拟合好的 Pipeline（做 SHAP 时取 `model.pipeline[-1]`）。

| 优先级 | 含义 | 界线（概率） | 界线怎么定 |
|---|---|---|---|
| 1 立即 | 得分最高的一部分事故 | ≥ 0.686 | 验证集得分最高的 15% |
| 2 紧急 | 两条界线之间 | 0.220 ~ 0.686 | — |
| 3 常规 | 得分很低，极少危及生命 | < 0.220 | 验证集上危及生命的事故只有 4% 低于它 |

两条界线只用验证集确定，定义在 `schema.json` 的 `triage` 段。

“危及生命”指致死或极重伤。它来自事故表的 `enhanced_severity_collision` 字段：按伤情记录的警区把事故分为致死、极重伤、中度重伤、较轻重伤、轻伤五级。
这个字段之前没有用过；测试集 92.6% 的事故有这一分级，下表中涉及“危及生命”的数字都在这部分事故上计算，致死事故在全部事故上计算。

测试集（完整信息）上每一级里实际是什么：

| 优先级 | 事故数 | 占比 | 致死 | 官方“重伤” | 轻伤 | 危及生命的比例 |
|---|---|---|---|---|---|---|
| 1 立即 | 3,152 | 12.8% | 252 | 1,587 | 1,313 | 22.0% |
| 2 紧急 | 15,156 | 61.4% | 115 | 3,846 | 11,195 | — |
| 3 常规 | 6,371 | 25.8% | 1 | 486 | 5,884 | 0.9% |

整体的危及生命比例是 6.2%。368 起致死事故中，252 起（68%）在第 1 级，只有 1 起在第 3 级。

最低验收标准与结果（测试集，完整信息）：

| 验收项 | 要求 | 实测 | 结果 |
|---|---|---|---|
| 危及生命的事故被排到第 3 级的比例（漏判率） | ≤ 5% | 3.8% | 通过 |
| 致死事故被排到第 3 级的比例 | ≤ 1% | 0.3% | 通过 |
| 第 3 级占全部事故的比例（能腾出多少力量） | ≥ 20% | 25.8% | 通过 |
| 第 1 级的危及生命比例相对整体的倍数 | ≥ 3 倍 | 3.5 倍 | 通过 |

标准的来历要说清楚：

- **漏判率 ≤ 5%** 取自创伤分诊领域通用的标准（美国外科医师学会创伤委员会）。
- **其余三项是本项目自定的最低要求**，数值在看到先期实验结果之后才确定，不是事先约定的。它们写在 `schema.json` 里，每次训练自动核对并记入 MLflow，可以按实际需要收紧。
- **同一套通用标准里的“过度分诊 25–35%”没有达到。** 第 1 级里 42% 是官方口径的轻伤事故；按“危及生命”口径，78% 不是。也就是说，第 1 级的含义是“优先核实和派出”，不是“已确认危重”。

### 4.2 信息不全时

| 测试集场景 | 1 / 2 / 3 级占比 | 危及生命漏判率 | 致死漏判率 | 第 1 级倍数 |
|---|---|---|---|---|
| 完整信息 | 12.8% / 61.4% / 25.8% | 3.8% | 0.3% | 3.5 |
| 缺天气观测 | 13.1% / 60.9% / 26.0% | 3.6% | 0.3% | 3.5 |
| 缺道路与环境 | 12.6% / 63.9% / 23.6% | 3.5% | 0.5% | 3.4 |
| 缺车辆 | 9.6% / 73.1% / 17.3% | 3.7% | 0.3% | 3.3 |
| 缺伤亡人员 | 7.5% / 73.7% / 18.8% | 3.2% | 1.1% | 3.5 |
| 缺车辆 + 伤亡人员 | 3.7% / 93.1% / 3.2% | 0.6% | 0.0% | 2.5 |

信息越少，模型越倾向于把事故放在第 2 级：漏判率不升，但分流作用减弱。车辆和伤亡信息都没有时，93% 的事故落在第 2 级，模型基本不起作用。
缺伤亡人员信息时致死漏判率为 1.1%，略高于 1% 的要求；验收只针对完整信息。

### 4.3 为什么不做“严重 / 不严重”的判定

- **实测上限**：把模型当二分类器，召回 85% 时精确率约 35%，要标记约 60% 的事故；精确率 60% 时召回只有约 25%。
- **加数据无效**：把三张表里剩余的字段全部加入（警察是否到场、警区、地方当局、车型、离家距离等），召回 85% 处的精确率只从 34.9% 到 35.5%；改为按每名伤亡人员建模再汇总，为 35.2%。
- **换目标也无效**：只预测致死时 ROC-AUC 约 0.90，但致死只占 1.5%；预测“致死或极重伤”为 0.79，与官方“重伤”口径的 0.74 相差不大。
- **缺的信息不公开**：决定伤情的撞击速度、安全带与头盔使用、气囊是否弹出等不在 DfT 公开数据里。

排序能力足以分级，但不足以下二分结论，所以输出改成了优先级。

## 5. 训练历程

| 版本 | 训练数据与做法 | 输入列 / 编码维度 | test PR-AUC | test ROC-AUC | 输出 |
|---|---|---|---|---|---|
| 1 | 事故表 + 天气观测 | 21 / 93 | 0.3732 | 0.6432 | 概率，阈值 0.5 |
| 2 | + 车辆表 + 伤亡表 | 226 / 313 | 0.5018 | 0.7432 | 概率，阈值 0.5 |
| 3 | 同版本 2，加信息遮蔽增强 | 226 / 313 | 0.4992 | 0.7404 | 概率，阈值 0.5 |
| 4 | 同版本 3，阈值改为 0.368 | 226 / 313 | 0.4992 | 0.7404 | 召回 85% 的二分结论 |
| 5（当前） | 同版本 3，按伤情等级加权，三级优先级 | 226 / 313 | 0.5060 | 0.7415 | 三级优先级 |

五个版本的切分、行数完全相同；PR-AUC 和 ROC-AUC 都按官方“致死或重伤”口径计算，可直接比较。
版本 1–3 在阈值 0.5 下的测试集召回分别是 0.520、0.689、0.657。

### 版本 1：事故表 + 天气观测

- **数据**：DfT 2024–2025 事故表（202,452 起）与逐小时天气观测，由 memberA 清洗、匹配并切分；符合建模条件的 164,850 起。
- **输入**：经纬度、限速、车辆数量、6 项天气观测、10 个道路与环境编码，加上时间和日照的派生特征。
- **结果**：三种树模型调参后验证集 PR-AUC 为 0.3885 / 0.3884 / 0.3872，几乎打平；调参只比基线高约 0.01。
- **结论**：瓶颈在信息量，不在算法或超参。事故表只描述“在哪、什么路、什么天气”，不包含“谁撞了谁”。

### 中间实验：事故表里未使用的字段（未采纳）

把警区、地方当局、道路编号、路面危险物等 8 个字段接入后，测试集 PR-AUC 只从 0.3732 升到 0.3765。
提升太小，不值得改动四人共用的 `schema.json`，没有采纳。

### 版本 2：加入车辆表和伤亡表

- **新增数据**：DfT 同期的车辆表（367,462 行）和伤亡表（256,155 行），按 `collision_index` 关联，建模样本覆盖率 100%。
- **处理方式**：一起事故有多辆车、多名伤亡人员，聚合为定宽特征——每个编码的计数，以及年龄等数值的最小/最大/均值，共 205 个新输入。
- **结果**：测试集 PR-AUC 0.3732 → 0.5018，ROC-AUC 0.6432 → 0.7432，重伤召回 0.520 → 0.689。
- **分组贡献**（先期实验，同一组 LightGBM 参数，测试集 PR-AUC）：只加车辆属性 0.427，只加碰撞过程 0.411，只加伤亡描述 0.467，三者全加 0.497。
- **发现的问题**：对信息缺失不稳健（见第 3 节）。

### 版本 3：信息遮蔽增强

- **改动**：训练集加入抹掉部分信息的副本，使模型在信息不全时退回到合理预测。
- **结果**：完整信息下与版本 2 基本持平；信息缺失场景全面改善，其中伤亡信息缺失时 PR-AUC 0.388 → 0.436。

### 版本 4：按召回目标设定阈值

- **改动**：模型与版本 3 相同（用 `--from-run` 重建，指标完全一致），只把决策阈值定为验证集召回 85% 对应的 0.368。
- **结果**：测试集召回 0.657 → 0.834，精确率 0.420 → 0.354，要标记 60% 的事故。作为调度依据不可用，因此被版本 5 取代。

### 版本 5：按伤情等级加权 + 三级优先级（当前）

- **新用到的数据**：事故表里的五级伤情 `enhanced_severity_collision`。它是结果字段，不进入模型输入，只用于样本权重、界线设定和验收评估。
- **样本权重**：权重 = 1 + 等级² / 2（轻伤 0 … 致死 4），取代原来按类别频率的加权，让模型把排序能力集中在更重的事故上。
  没有分级记录的警区，“重伤”按有分级地区重伤事故的平均等级（1.6）计。
- **输出**：三级优先级，界线与验收见第 4 节。
- **结果**：官方口径的 PR-AUC 0.4992 → 0.5060；致死事故的 ROC-AUC 为 0.885，危及生命为 0.787。
- **没有重新搜索**：版本 5 用 `--from-run` 沿用版本 3 选出的模型族和超参，只重训了最终模型。第 1 节的候选排行榜是在旧权重下得到的。

## 6. 复现与追踪

```bash
python -m src.data_pipeline all   # 清洗、匹配天气、聚合车辆与伤亡、时间切分
python -m src.database            # 合并全部 CSV 为 data/road_collisions.sqlite
python -m src.train               # 基线 + Optuna + MLflow 追踪与注册
python -m src.train --from-run RUN_ID   # 按某个最终 run 的选择重建并注册，不重新搜索
```
