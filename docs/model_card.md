# Model Card：道路事故严重程度与派单优先级模型

本卡片说明模型的用途、表现、适用边界与风险。对应代码：`src/train.py`、`src/triage.py`、`src/evaluate.py`、`src/explain.py`；详细评估见 `docs/report_C_evaluation.md`。

---

## 1. Model Details

| 项 | 内容 |
|---|---|
| 模型类型 | XGBoost 二分类器（MLflow `production` 别名指向的版本）+ 两条概率界线构成三级派单 |
| 产物 | MLflow `road-severity-model`，别名 `production`，`src.triage.TriageClassifier` |
| 输入 | 226 个原始字段（时间、地点、道路、天气、车辆、伤亡人员），编码后约 313 维 |
| 必填输入 | 仅时间与经纬度；其余字段可以缺失 |
| 输出 | `predict_proba` 给出严重程度概率；`predict` 给出优先级 1 立即 / 2 紧急 / 3 常规 |
| 训练数据 | 英国 DfT 道路事故统计 2024-01-01 ~ 2025-12-31，逐小时天气数据 |
| 时间切分 | train 2024-01-01 ~ 2025-06-14（115,535 行）／val 2025-06-15 ~ 2025-09-24（24,636）／test 2025-09-25 ~ 2025-12-31（24,679） |
| 标签 | 官方口径"致死或重伤"（`collision_severity ∈ {1, 2}`） |
| 版本 / 日期 | v5，2025-12 |
| 负责人 | B（训练与注册）、C（评估、校准与解释） |

预处理随模型一起保存（`sklearn` Pipeline），部署端只需按 `schema.json` 提供原始字段，不依赖任何训练侧代码。

---

## 2. Intended Use

**适用**

- 急救调度在接警阶段对事故按轻重缓急**排序**，决定核实与派车顺序。
- 在信息不完整（如仅有时刻与地点）时提供一个可用的初始排序。

**不适用**

- 作为"严重 / 不严重"的**判定器**。默认阈值（0.5）下精确率 0.4562、召回 0.5433；把召回拉到 92.7% 需要标记 75% 的事故（第 1+2 级）。
- 替代现场医学判断。第 1 级的含义是"优先核实并派出"，不是"已确认危重"：第 1 级中按官方口径有 42% 是轻伤，按"危及生命"口径有 78% 并非危及生命。
- 用于理赔定责、司法鉴定等需要确定性结论的场景。
- 对未见过的地区、年份或记录体系外推而不做重新评估。

## 3. Factors

与表现相关的已知因素：

- **信息完整度**：车辆信息缺失时测试集 PR-AUC 降至 0.4593，伤亡人员信息缺失时降至 0.4363；两类同时缺失时 0.360 / 0.626，且 93% 的事故落入第 2 级，模型基本失去分流作用（数值来自 B 的信息缺失实验）。
- **记录方式**：部分字段的"未知"取值反映填报渠道（自助报案、警员现场记录），不是物理原因。
- **环境**：城市道路、白天、限速 ≤30 的切片漏判率最高（日间时段 6.08%），乡村、高速、夜间表现更好；分群审计覆盖城乡 / 光照 / 限速 / 时段四个维度，结果见 `artifacts/evaluation/segments_test.csv`。
- **时间段**：切分按时间，训练与测试之间存在自然漂移（详见第 7 节与漂移报告）。

## 4. Metrics

测试集（完整信息、时间外推）：

| 指标 | 数值 |
|---|---|
| PR-AUC | 0.4991 |
| ROC-AUC | 0.7379 |
| F1（阈值 0.5） | 0.4960 |
| 精确率 / 召回 | 0.4562 / 0.5433 |
| 平衡准确率 | 0.6610 |
| Brier | 0.1838（isotonic 校准后：0.1630） |
| ECE（10 等频分箱） | 0.1305（校准后：0.0063） |

所有值与 MLflow 中 `production` 版本的记录逐项对账，22 项零差值。

**不使用准确率**：重伤约占 25%，全部预测为"轻伤"即可得到约 75% 的准确率，该数字无法反映分流能力，因此选模指标为验证集 PR-AUC。

三级分流的验收（测试集）：

| 验收项 | 要求 | 实测 | 结果 |
|---|---|---|---|
| 危及生命事故进入第 3 级的比例 | ≤ 5% | 3.86% | 通过 |
| 致死事故进入第 3 级的比例 | ≤ 1% | 0.27% | 通过 |
| 第 3 级占全部事故的比例 | ≥ 20% | 24.53% | 通过 |
| 第 1 级中危及生命事故的富集倍数 | ≥ 3 倍 | 3.51 倍 | 通过 |

界线（来自验证集）：0.2011（常规 / 紧急）、0.6644（紧急 / 立即）。isotonic 校准后重映射为 0.1290 / 0.4530，分级结果四项验收不变。

## 5. Training and Evaluation Data

- 数据来源：英国交通部（DfT）道路安全开放数据，事故 / 车辆 / 伤亡三表按 `collision_index` 关联，并叠加逐小时气象观测。
- 标签：`collision_severity` ∈ {1 致死, 2 重伤} 记为正类；3 轻微记负类。
- 伤情五级 `enhanced_severity_collision` **不进入模型输入**，只用于样本权重、界线与验收，避免标签泄漏。
- 预处理（中位数填补、标准化、独热编码）仅在训练集拟合；验证集与测试集只做 transform，`src/features.py::check_preprocessing` 会断言这一点。
- 训练使用伤情等级加权（`1 + 等级²/2`），目的是把排序能力集中在重伤区间；副作用是概率整体偏高，由 C 在验证集上做单调校准。

## 6. Ethical Considerations

- **记录方式偏差**：`vehicle_left_hand_drive`、`sex_of_driver` 等字段的主要信号来自"未知"取值，它反映填报渠道而非物理原因，可能导致对自助报案事故的系统性误判。
- **地域与社会经济因素**：驾驶员与伤亡人员的居住地贫困指数进入模型，存在地域偏见风险，需在分群审计中持续监控。
- **自动化偏差**：分级影响派车顺序，调度员可能过度依赖分数；界面应同时展示不确定性与单样本解释，并保留人工覆盖。
- **信息缺失下的公平性**：信息缺失本身与报案渠道相关，而缺失时模型基本失效（93% 落入第 2 级），可能造成群体间待遇差异。
- **使用边界**：不得用于对个人作出医疗、保险或法律上的不利决定。

---

## 7. Caveats and Limitations

- 决定伤情的关键信息（撞击速度、安全带与头盔使用、气囊状态）不在公开数据中，构成性能上限。
- 车辆与伤亡信息同时缺失时基本失去分流能力。
- 校准器在 2025 年下半年验证集上拟合，跨年稳定性未知；概率为校准后数值，SHAP 贡献为 log-odds 尺度，展示时不可混用。
- 两条界线与两项验收下限（三级占比、富集倍数）为事后确定，存在迎合风险，建议用独立时间段复核。
- 训练与测试之间有时间漂移，主要来自气象量的季节差（`temp` PSI 0.57、`rhum` 0.51、`pres` 0.23）；`age_of_vehicle` 因 2025-06 后整列缺失已在特征工程阶段排除。漂移清单见评估报告第 7 节。
- 分群审计仅覆盖城乡 / 光照 / 限速 / 时段四个维度，不是完整的公平性审计。
